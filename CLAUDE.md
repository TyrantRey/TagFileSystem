# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

TagFileSystem is a per-root daemon: it watches a managed folder, keys every file in SQLite, parses tags and add-on functions out of names (`@@make_copy__.jpg__backup/2024--trip/img--raw.jpg`), runs user-written add-ons from `script/` on the files that ask for them, and records runs, traces, provenance and problems so a human, the `tfs` CLI or later an MCP client can query them. Python 3.12, managed with `uv` (src layout, `uv_build` backend). Every source file starts with `# Code by AkinoAlice@TyrantRey`.

`DESIGN.md` is the approved v1 design (2026-08-30) and wins over this file for **target** behaviour; this file describes the code **as it is**. Read `DESIGN.md` before changing the name grammar, schema, configuration, CLI or run semantics; update both when behaviour changes. `README.md` is the user-facing short version.

## Commands

```bash
uv sync                                   # install deps + editable install (registers the `tfs` script)
uv run tfs init <dir>                     # create a root: <dir>/.tfs/{config.toml, db/, token} + <dir>/script/
uv run tfs start [-d] [--force]           # reconcile + watch (foreground; -d detaches, output in .tfs/daemon.out)
uv run tfs list | query -t x --json | reload | stop
uv run ty check src tests                 # type check (must be clean)
uv run pytest -q                          # tests (~1 min; every test builds its own temporary root)
```

- Every command takes `--root <dir>`; otherwise the root is discovered by walking up from CWD like git.
- Linting/formatting is configured for Trunk (`.trunk/trunk.yaml`: ruff `B,D3,E,F` with `E501` ignored, black, isort profile=black, bandit, markdownlint, prettier). The `trunk` CLI is not installed on this machine.
- Tests: `tests/helpers.py` has `fetch` / `metadata_of` / `tag_of` (assert-narrow `Optional` results so `ty check tests` stays clean). Tests that load add-ons carry a `clean_modules` fixture that drops `tfs_addons.*` from `sys.modules`. Daemon/CLI tests pick a free port and write it into the root's `config.toml`.

## Architecture (by layer, bottom up)

**Paths and root (`core/paths.py`, `root.py`)** — DESIGN §2. `is_anchored` / `posix_key` / `has_parent_reference` answer path questions for *either* OS flavour. `Root.init(dir)` creates the layout (refuses if the dir, an ancestor or a descendant already has `.tfs/`, or if a file is in the way; cleans up on failure); `Root.discover(start)` walks up (`NotARoot`). `Root.relative(path)` **resolves** the path (symlinks, `..`, 8.3 names, case) and returns a `PurePosixPath` key or raises `OutsideRoot`; `absolute(key)` rejects anchored keys, `..`, and drive-relative `D:x` on Windows; `zone(path)` → `Zone.TFS` (any `.tfs` component, `os.path.normcase`) / `SCRIPT` / `DATA`. `Lock(root).acquire(force=False)` creates `.tfs/lock` **with content atomically** (temp file + `os.link`; `O_EXCL` fallback), judges staleness by pid on this host (`pid_alive`: never `os.kill` on Windows, access-denied = alive) and by age for other hosts, evicts stale locks by renaming them away, never evicts an unreadable lock younger than 2 s, and gives up after 5 s (`LockHeld` carries the holder's `LockInfo`).

**Configuration (`config.py`)** — `Config` models `.tfs/config.toml`: `[logging] level/file`, `[daemon] bind/port/stop_timeout_seconds/run_warn_after_seconds`, `[remotes]`. `extra="forbid"`, strict numeric fields, `bind` must be an IP, `logging.file` root-relative without `..` or a drive, remotes are **verbatim strings** that must be absolute in either flavour. `loads/load` raise `ConfigError`; `dumps/write` use a small TOML writer. There is no `.env` any more.

**Name grammar (`services/tagging.py`, `core/interface/tag.py`)** — DESIGN §3. `TaggingParser.parse(segment)` parses one directory name or filename stem; `parse_path(root_relative_path, is_file=True)` parses every segment and merges parent-first (tags = union, first occurrence wins; actions = distinct `(name, args)` parent-first, filename last). Anchored paths and `..` are errors. `ActionCall` (frozen; `name` lowercased, `[a-z][a-z0-9_]*`, no leading/trailing `_`; `args` split on `__`, verbatim, NFC) and `Tag` (frozen, normalized) reject illegal characters (`: / \ < > | ? * "` and line breaks) and marker text. A bad marker becomes a `ParseProblem` and the rest still parses. `split_extension` drops the filename suffix unless it contains marker syntax.

**Persistence (`database/sqlite.py`, `database/migrations.py`, `database/action_store.py`, `core/interface/{database,file_metadata,action}.py`)** — DESIGN §7. `SQLiteBackend.init_database(path, root_dir)` opens one connection (`check_same_thread=False`, WAL, foreign keys) behind an `RLock` (`@transactional` writes, `@locked` reads; nested calls join the outer transaction) and runs `apply_migrations` (`PRAGMA user_version`; `SchemaTooNew`; `MigrationError` for a rootless open of a DB with absolute paths; migration 1 creates all tables, adds `files.mtime_ns`, rewrites `files.path` to root-relative POSIX, soft-deletes rows it cannot key and parks dead duplicates under `.tfs/duplicates/`). **Paths are stored as root-relative POSIX keys** (`backend.key()`); `TaggedFile.path` is the key, `original_path` the host path. Files/tags semantics: `insert` revives a soft-deleted row in place, `delete` is soft, `modify` renames, `set_file_tags` makes the exact set, queries exclude deleted rows unless asked, `query_files(path_prefix=)` answers "under `@@f`". `ActionStore(backend)` shares the connection and lock: `register_action` (upsert by `(name, script_hash)`, monotonic `loaded_at`), `find_run`/`start_run` (key `(file_hash, action, hook, canonical args)`; `RunExists` unless `retry_of` names a final run with the same key), `finish_run` (terminal; `RunAlreadyFinal`), `mark_interrupted`, `add_trace`, provenance (`emitted` beats `observed`, repeated `observed` accumulates `ambiguous`), problems with `delivered_at`, `file_history` (+ `.timeline`), `query_runs(path_prefix=)`. `canonical_json` is the only JSON writer (sorted keys, explicit encoder, `TypeError` otherwise, no NaN).

**Add-on API (`action.py`, `addons/binding.py`, `addons/loader.py`)** — DESIGN §4.1–4.2, §4.4. `from tag_file_system import action`: `@action.added() / .modified() / .removed(on_move=False) / .tagged("x") / .crit() .err() .warn() .info()` mark a function (bare `@action.added` is a `TypeError`); `action.TagDir` / `action.Remote` annotate path-valued args. `binding`: parameters after `(path, metadata, ctx)` (2 for problem handlers) are validated per parameter through cached `TypeAdapter`s; `raw_by_name` gives the run-key args (slug strings keyed by parameter name) even when binding fails; bare `Path`, `async def`, `*args`, positional-only and keyword-only fixed params are `SignatureError`s at load. `AddonLoader.load_all()` execs every `script/*.py` from source into `tfs_addons.<name>` (no `__pycache__`); imports *from* a script (helpers `_x.py`, sibling add-ons) are served by `_ScriptFinder`, last in `sys.meta_path`, which resolves by the importing code's `__file__` to that root's `script/` (nothing on `sys.path`, installed modules are never shadowed, helpers shared within a root and reloaded on change, circular sibling imports resolve like packages). Rules: bad filenames → `addon.filename` (WARN), import failures incl. `SystemExit` → `addon.import` (previous version kept), bad signatures → `addon.signature`, a second handler per `(hook, tag)` → `addon.duplicate_handler`, no handlers → `addon.empty`, store failure → `db.unwritable`.

**Runner (`addons/runner.py`, `addons/context.py`)** — DESIGN §4.3, §4.5, §6. `ActionRunner.on_file(hook, path, file, parsed, source, parent, moved)` / `on_tag(...)` run handlers parent-first: key first (`find_run` → skip), provenance guard (a file never re-triggers the action that produced it, for `added`/`modified`), then bind, `start_run`, call the handler with stdout/stderr/logging routed into its trace by a **thread-local dispatcher** installed once per process (streams and the root logger level are restored after each run), and finish `ok`/`failed`/`interrupted` with the matching problem. `ctx.copy/move/write/delete/emit` keep the DB in step (`Indexer`), record `emitted` provenance and chain the produced file's own tags and `@@` functions (`source=chain`, `parent_run_id`, depth ≤ 8). `ctx.spawn` makes the run thread-backed until `ctx.done()`; a dying thread fails the run; `check_overdue` raises `run.overdue` once; `stop(timeout)` interrupts leftovers (P0). `problem()` records, then dispatches to `loader.problem_handlers` (level and above) with a thread-local recursion guard; problems raised by runs a handler starts are delivered after it returns. `retry` only for failed/interrupted runs whose file exists, at most `MAX_RETRIES` deep.

**Daemon (`services/daemon.py`, `services/indexer.py`, `services/control.py`, `core/logger.py`)** — DESIGN §5, §8. `Indexer.index(path)` is the one place a file becomes a row (stat; hash unless `(size, mtime_ns)` match; insert/update; tags = the name's tags plus whatever the previous row carried beyond *its* name). `Daemon(root, control=True)`: `startup()` = lock (`lock.stale`/`lock.overridden`), `mark_interrupted` leftovers (`run.interrupted` P0), control server, `load_all`, `replay_undelivered`, `reconcile()`; `run_forever()` feeds `watch(root)` batches to `process_changes()` and ticks `check_overdue`; `shutdown()` = `runner.stop`, control stop, lock release, DB close. `process_changes` consolidates (deleted > added > modified), routes by zone (`.tfs` ignored, `script/` → loader, data → files), detects **moves** (vanished row whose hash matches an added file → `backend.modify`, `removed(on_move=True)` for `@@` dirs left), reconciles added directories, fires `on_tag` for new tags then `on_file`, and attributes changes seen while runs are in flight as `observed` provenance (+ P2). `ControlServer` serves `/health`, `/stop`, `/reload`, `/actions`, `/files` with `Authorization: Bearer <.tfs/token>`; `ControlClient` is what the CLI uses. `configure_logging` is called by `tfs start`, never at import.

**CLI (`cli.py`)** — DESIGN §8. Typer app with exactly `init`, `list`, `query`, `reload`, `start`, `stop`. Client-first: `_client()` turns an unreadable config/token into `ControlUnavailable` too, so `list`/`query` fall back to loading `script/` in-process / opening the DB directly (refused on a network mount: `is_network_path`); `reload` needs the daemon; `stop` falls back to the pid in `.tfs/lock` **only when the lock's hostname is this host** (SIGTERM on POSIX; `taskkill /F` on Windows, reported as "forced"), and waits `stop_timeout_seconds + 5` by default; `start -d` refuses when a daemon already answers, re-launches `python -m tag_file_system.cli --root <root> start` detached and polls `/health` for up to 15 s, failing with the tail of `.tfs/daemon.out` if the child dies. `query` validates `--under` (root-relative dir) and blank `--tag` (exit 2); `--mime image/*` is a family match. `list` prints the daemon's per-script load problems (`Daemon.load_problems()`, fed by the loader's `report`). `Daemon(apply_logging=True)` (set by `tfs start`) makes `reload` re-apply `[logging]`; `/health` reports `"stopping"` once a stop is requested; a final `reconcile()` runs after the watch loop ends so events queued behind a long handler are not lost.

## Gotchas

- Two unrelated `Tag` models: `core/interface/file_metadata.Tag` (`name`, `tag_id`, `time_added` — DB queries) and `core/interface/tag.Tag` (`name` — the parser). Check which one you import.
- `FileMetadata.file_format` is the suffix with its dot (`.txt`), `file_type` without it, `mime_type` separate.
- Run keys are content hashes: two identical files under one `@@` function share a key (the second gets no run); a binding failure is a dead key until `ctx.retry`.
- The runner replaces `sys.stdout`/`sys.stderr` with a pass-through dispatcher and raises the root logger to INFO once per process (needed to capture add-on output); pytest's capture is wrapped, not replaced.
- Long-running SQL from an add-on thread blocks the watch loop (one connection, one lock) — keep add-on DB use short.
- `watchfiles` reports a directory rename as one event for the directory: the daemon reconciles the subtree; nothing is done per child by the watcher.
